# Skill 7 - 自动岗位监控（文雪求职知识库）

## 路径基准（第一步先执行）
- 本技能所有相对路径（01_岗位搜集与背调/…、07_原始材料库/…、99_系统与规则/… 等）均以 D:\Obsidian\SCM-Career 为根目录。
- 执行前先确认当前工作目录是 D:\Obsidian\SCM-Career；若不是或不确定（例如定时任务未设置工作空间），所有读写路径一律用绝对路径 D:\Obsidian\SCM-Career\…，禁止按错误的相对路径落盘。

## 触发方式
- 定时唤醒（每天 12:00，含周末），或用户说“执行 Skill 7”；run now 可随时手动触发，与计划时间无关。
- 自动化运行时：先读取 `WorkBuddy 自动化记忆文件（~/.workbuddy 下对应自动化的 memory；不存在则按 07_原始材料库 与岗位汇总表去重恢复）`（若存在）避免重复；运行后更新 memory.md 摘要；被中断后下次运行先按 07_原始材料库 与 岗位汇总表 去重恢复。

## 固定服务对象
文雪，山东大学供应链管理 2027 届毕业生（画像见 `00_战略与定位/文雪-求职目标画像.md`）。

## 来源规范（官方/权威优先，禁止 low 源）
【来源白名单 · 按优先级】
1. 🥇 目标公司官网校招页（如 careers.byd.com、各公司 campus/careers 页面）——**最优先，逐家核对**
2. 🥇 山大就业信息网 www.job.sdu.edu.cn（本校官方，用人单位正式发布的岗位/宣讲/双选会）——每轮必查：抓招聘信息/宣讲会/双选会栏目列表，提取含「供应链/计划/采购/物流/数据分析」的岗位
3. 🥇 国家大学生就业服务平台 ncss.cn / job.ncss.cn（教育部官方）；国聘网 www.iguopin.com（国企/央企官方）
4. 🥈 招聘软件：应届生求职网 www.yingjiesheng.com、BOSS直聘、猎聘、前程无忧、智联、牛客校招
5. 🥉 其他网页：各省市人社/就业官方平台、同层次/目标城市高校就业网（仅作补充线索，收录前尽量回官方核实）
【禁止 / 降权】
- 不收录来源：个人博客、无出处的聚合转载站、搜索引擎小站（jobui 及各类垃圾聚合站）；除非能在官方渠道核验到同一岗位，否则不收录或标注「⚠️ 来源待核验（不推荐）」。
- **聚合内容禁止（收录硬门槛）**：短视频/公众号/求职号整理的「聚合帖/合集视频」（抖音、小红书、微信公众号、B站等平台的个人求职号内容）一律只作线索，**禁止作为岗位来源收录**；必须回官方渠道或招聘平台核验到具体岗位详情页（含职责/要求/地点/投递入口四要素）后才能归档评分。同一来源链接同时对应多个岗位时，**禁止把该链接分别作为多家/多个岗位的来源重复收录**（一个链接 = 一条线索，须逐个回官方/平台核验）。
- 检索优先白名单域名（可用 site:域名 限定）；同一岗位存在官方源时，一律以官方源为准记录。
【检索方式】
- 直接访问白名单站点 + 站内检索（site:job.sdu.edu.cn 供应链 计划 采购 等）；单轮搜索 ≤ 10 次的上限不变。

## 登录平台半自动流程（BOSS直聘/猎聘/智联/前程无忧/脉脉等）
- **优先复用 Chrome 已登录会话**：已安装 WorkBuddy Web Access（浏览器自动化，CDP 复用 Chrome 已登录会话）时，直接复用用户 Chrome 里已登录的平台会话读取岗位，**登录过的平台不重复登录**。
- 无登录态的平台：不硬抓、不绕过登录/验证码；在对话中请求用户登录（内置浏览器打开链接由用户本人扫码/输密码），或自动阶段结束后在日报生成「📌 需你登录的平台清单」（平台名 + 目标公司 + 建议搜索词）。
- 用户提供 JD 的三种方式（任选其一，AI 自动提取并继续 归档→评分→背调 全流程）：
  1. 粘贴 JD 文本（对话里直接发）
  2. 发链接（AI 直接抓详情，可访问则抓）
  3. 发截图（AI 自动 OCR 提取文字）
- 登录由用户本人完成；不保存账号密码。

## 执行流程
1. **发掘候选（动态，不限于任何名单）**：以 `00_战略与定位/文雪-求职目标画像.md` 第 2.5 章「潜力企业筛选标准」为判断依据，动态发掘新企业——大厂旗下子企业/子品牌/独立事业部、幼年体企业（成长期/融资/扩产/新业务）、小而美的外企（行业隐形冠军、德日法瑞中小外企）、赛道好（快消/宠物/零售/新能源/智能制造/供应链科技）；参考线索池见 `01_岗位搜集与背调/🗂️ 候选线索池.md`（仅初始候选，**不作为检索边界**）。每发掘一家先做**初步筛选判断**（前景 / 有无供应链计划采购物流类岗位 / 口碑），不达标不收录。
2. **来源优先级（硬性排序）**：🥇 企业官网/官方招聘页/官方校招平台 → 🥈 招聘软件（BOSS直聘、猎聘、前程无忧、智联、应届生求职网、牛客校招）→ 🥉 其他网页（转载/聚合站仅作线索，收录前尽量回官方核实）。严格按「来源规范」白名单执行，不用 low 源。
3. **登录协作**：需登录才能看完整 JD 的招聘软件 → **优先复用 Chrome 已登录会话（WorkBuddy Web Access（浏览器自动化，CDP 复用 Chrome 已登录会话）；已登录过的平台不重复登录）**；无登录态则在对话中请求用户登录（内置浏览器打开链接由用户本人登录），登录后继续；不绕过登录、不保存账号密码。
4. **去重（按岗位方向，非按企业）**：同一家企业发布的**不同方向岗位**（如供应链计划、采购、物流、数据分析等）视为**独立岗位，分别收录、分别评分，不算重复**；仅当「同一企业 + 同一岗位方向 + 同一招聘批次/城市」时判定为重复并跳过。比对对象：`07_原始材料库` 与 `01_岗位搜集与背调/📋 岗位汇总表.md` 已有岗位（按评分笔记 frontmatter 的「公司名称 + 岗位方向」识别）。
5. **检索收敛（防无限膨胀）**：单轮全网搜索 ≤ 10 次；先「发掘→筛选→归档→评分→写入」一批（≥3 个）再决定是否扩大；超出预算先写入已找到的并出日报，剩余列入下轮待办。
6. **岗位级信息核验（收录硬门槛）**：**「简章/项目级」信息 ≠「岗位级」信息**——招聘简章的项目批次、方向分类（如“XX年度实习生-供应链及制造类”）、截止日期均为项目级信息，不代表该方向当前有具体岗位在招（具体岗位在官网/平台动态上下架）。**凡定位不到具体岗位详情页（须含明确岗位职责、任职要求、工作地点、投递入口四要素）的，一律只记入 `🗂️ 候选线索池`「待核实」，不得归档、不得评分收录**；须以官网/招聘平台当时在招的具体岗位页为准，核验通过后方可进入归档→评分流程。官方简章真实性核验 ≠ 岗位在招核验，两者缺一不可（海信教训：简章真实 ≠ 官网有岗在招）。
7. **归档**：写入 `07_原始材料库/{公司名}/{岗位名}（{方向}）/`（材料登记笔记，命名 `{材料类型}-{公司名}-{岗位名}（{方向}）-{日期}`），并同步 `🗂️ 候选线索池` 的「已考察记录」。
8. **Skill 1 评分**：按画像第 7 章自动评分并写入评分笔记（≥70 推荐；<70 且未触发红线 → `🗂️ 备选`；触发红线 → `❌ 已挂（红线）`）。
9. **Skill 2 背调**：对推荐与值得的备选岗位自动背调（**每轮上限 3-5 个，质量优先，按 Skill 2 完整六大板块**），写入背调报告并同步评分笔记。
10. **生成「岗位日报」**：三档清单（✅推荐 ≥70 / 🗂️备选 <70 / ❌红线-不建议），附背调摘要、🔑需登录/已复用登录标注、待办；**对话中完整输出 + 摘要（3-5 行）追加到 `01_岗位搜集与背调/📅 岗位日报归档.md`**（只追加不覆盖、标注日期）。
11. **等待用户**：用户挑选后回复“为 X 执行 Skill 3”，进入简历定制（需用户确认后写入）。

## 自动化环境写入方法（防卡死）
- 自动化环境已授权写知识库（D:\Obsidian\SCM-Career），直接用普通写文件命令；若首次提示需要授权，申请一次即可。
- 环境里 `python`/`py`/`python3` 通常**不在 PATH**：不要反复尝试这些命令，直接用下方 Python 完整路径；`WorkBuddy 运行时依赖工具` 若调用后长时间未返回则放弃它，改用已知路径。
- 写 UTF-8 中文文件推荐方式（PowerShell 把脚本通过 stdin 管道传给 Python，避免写临时脚本被拒）：
  `$code = @'...脚本...'@; $code | & <WorkBuddy 可用的 python 完整路径，优先系统 python/py> -X utf8 -`
- **防卡死**：同一写入连续失败 2 次即停止重试，把「未能写入的内容」记入 memory.md 与问题日志，在日报中说明后继续；连续 3 分钟无进展就先把已完成的写入并出日报，不要无限等待。

## 约束
- 禁止编造；无法确认标注“未收录/未披露”。
- 届别核验（**收录/归档前执行**）：JD 发布批次须与用户届别（2027 届）核对；JD 出现上一届字样（如「26届应届生/毕业生」「2026届校招」/2025 年发布）→ **不得归档评分收录**，直接记入 `🗂️ 候选线索池`「待核实」或标「备选-届别待确认」，日报单列「⚠️ 届别不符」；届别未标注/转载模糊 → ⚠️ 届别待核实，不当作有效投递机会。
- 背调完整性：背调报告文件未实际写入时，不得将状态标为 ✅已背调、不得链接不存在的报告文件；标 ⚠️ 背调待补充，并在日报说明原因。
- **命令被权限/沙箱限制拦截降级**（沙箱/权限限制）：若基础命令（如 Get-Location / echo）连续失败，**不要反复重试**；改为「只公开检索 + 输出完整结构化日报（企业/岗位/地点/薪资/来源/发布日期/届别核验/初步评分/背调/待办）」；所有写入项在日报中列明并标「待普通对话代劳」，结束后提示用户把日报发到普通对话由 AI 代写；不空转、不卡死。
- 来源日期真实性：「发布日期」必须是来源页/资料明确标注的发布（公告）日期；无明确日期填「未确定」；禁止用归档日期/检索日期冒充发布日期、禁止编造。「归档日期」为录入知识库日期，仅用于排序/去重。
- 需登录的平台不绕过登录/反爬，不保存账号密码；先公开抓取，需登录则请求授权或由用户粘贴 JD。
- 每轮背调上限 3-5 个。
- 日报不隐藏任何岗位（红线岗位列出但标注“不建议投递”）。
- 自动化运行环境可能网络受限（默认沙箱）：网络/工具受限时，能抓的公开来源照常抓取，需登录平台记录“需授权”列入日报待办，不卡死、不中断；Skill 1/2 自动写入知识库。
- 若上一轮被中断（如 run now 未产出）：先核对已有材料与评分笔记去重，避免重复收录。

## 全局规则（所有 Skill 通用）
1. 每次执行 Skill，先在对话中输出完整内容预览（Skill 1/2 以「岗位日报」呈现）。
2. Skill 1（评分）与 Skill 2（背调）为自动执行流程：找到岗位后自动评分、背调、写入知识库，无需用户确认。
3. Skill 3（简历）/Skill 4（备考）/Skill 5（复盘）/Skill 6（周报）须先询问“请确认以上内容无误，确认后我将写入知识库并生成 Word 文档。”，用户回复“确认”或“可以”后才写入。
4. Word 排版规范（自动应用）：
   - 封面页：标题 + 公司名 + 岗位名 + 日期 + “内部使用·求职调研”
   - 目录（含超链接，可点击跳转）
   - 页眉：文档名称
   - 页脚：页码（第 X 页 / 共 Y 页）
   - 标题自动编号（一、1.1、1.1.1 三级）
   - 中文宋体 / 英文 Times New Roman，小四，1.5 倍行距
5. 禁止编造信息，无法确认的标注“未收录/未披露”。
6. 禁止在输出中提及“AI助手”或“作为AI”。
7. **问题日志（即时记录 + 收尾强制自检）**：执行过程中发现问题（工具异常、规则缺口、数据/文件/链接异常等），即时补充到 `99_系统与规则/求职知识库问题日志.md`（问题/原因/处理/状态）并在对话中告知；**本次执行结束前必须收尾自检**：本轮有无需修订的规则、异常数据/文件/链接、踩过的坑？有则先补记问题日志（新增一行）再结束，不省略。
8. 非重大事项不询问：除 Skill 3/4/5/6 规则明确要求「确认后写入」的流程外，常规动作（归档/评分/背调/转换格式/生成 PDF/更新索引与日志等）直接完成并在对话中告知结果，不逐项询问；仅在涉及删除用户文件、账号/资金/隐私、或可能造成不可逆影响时，先征询用户。
