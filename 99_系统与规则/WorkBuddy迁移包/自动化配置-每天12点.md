# WorkBuddy 定时自动化配置（每天 12:00 执行 Skill 7）

> 在 WorkBuddy 客户端 →「自动化」→「新建自动化」中按下面配置；调度规则与 Codex 版完全一致（每天含周末 12:00）。

## 名称
Job-Pipeline-Driver（每天12:00）

## 调度（RRULE）
FREQ=WEEKLY;BYHOUR=12;BYMINUTE=0;BYDAY=SU,MO,TU,WE,TH,FR,SA

（WorkBuddy 支持可视化选"每天/每周"，也可用高级模式直接填 RRULE；与 Codex automation.toml 相同）

## Prompt（直接复制）
时间：每天 12:00（每天执行，含周末）
触发内容："执行 Skill 7（自动岗位监控）"
执行要求：
1. 先读取 WorkBuddy 自动化记忆文件（~/.workbuddy 下对应自动化的 memory；若不存在则按 07_原始材料库 与岗位汇总表去重恢复），避免重复已做工作。
2. 按 Skill 7 规则：以画像第 2.5 章「潜力企业筛选标准」动态发掘新企业（大厂子企业/幼年体/小而美外企/赛道好；参考线索池见 01_岗位搜集与背调/🗂️ 候选线索池.md，仅初始候选不作为边界），每发掘一家先做初步筛选判断；来源优先级：🥇 企业官网/官方招聘页 → 🥈 招聘软件（BOSS直聘/猎聘/前程无忧/智联/应届生求职网/牛客校招）→ 🥉 其他网页（仅作线索回官方核实）；需登录平台优先复用 WorkBuddy Web Access（浏览器自动化，复用 Chrome 已登录会话，登录过的不重复登录），无登录态则请求用户登录后继续；单轮全网搜索 ≤ 10 次，先「发掘→筛选→归档→评分→写入」一批（≥3个）再扩大；去重 → 归档 07_原始材料库 → Skill 1 自动评分 → Skill 2 自动背调（每轮上限 3-5 个，质量优先）→ 生成岗位日报；届别核验：JD 发布批次与用户 2027 届核对，上一届批次标 ⚠️ 届别待确认（不标推荐）、模糊标 ⚠️ 届别待核实；背调报告文件未写入时不得标 ✅已背调或链接不存在的报告（标 ⚠️ 背调待补充）；来源日期真实性：发布日期须为来源页/资料明确标注的发布日，无则写「未确定」，禁止用归档日期冒充或编造。
3. 网络/工具受限时：能抓的公开来源照常抓取；需登录平台优先复用 WorkBuddy Web Access，无登录态记录"需授权"列入日报待办，不卡住、不编造、不绕过登录；命令被权限/沙箱限制拦截时不空转重试，降级为「只公开检索 + 输出完整结构化日报（企业/岗位/地点/薪资/来源/发布日期/届别核验/初步评分/背调/待办）」，写入项标「待普通对话代劳」并结束。
4. 本轮完成后：a) 把摘要（新增岗位/评分/背调/待办/问题）写入自动化记忆文件；b) 在对话中输出完整岗位日报；c) 把日报摘要（3-5 行）追加到知识库 01_岗位搜集与背调/📅 岗位日报归档.md（只追加不覆盖、标注日期）。
5. 写文件方法（自动化环境）：知识库 D:/Obsidian/SCM-Career 已授权可写，直接用普通写文件命令；若首次提示需要授权，申请一次即可。python 优先系统 python/py，不在 PATH 时用 WorkBuddy 运行时自带 python 完整路径（加 -X utf8），脚本经 stdin 管道传入写 UTF-8 文件；同一写入连续失败 2 次即停止重试，记入记忆文件与问题日志并在日报说明；连续 3 分钟无进展先输出已完成的，不无限等待。
6. 发现问题即时记入 99_系统与规则/求职知识库问题日志.md。
提醒：需要电脑开机 + WorkBuddy 应用运行，到点才会执行；run now 可随时手动触发，与计划时间无关。
