# 网页生成与维护说明（供 WorkBuddy / 助手修复网页时阅读）

> 用途：说明"文雪求职小窝"网页的生成原理与修法，便于 AI 助手（尤其 WorkBuddy）接到"网页有问题"时直接定位修复。

## 一、网页怎么来的（架构）
1. 源数据 = 知识库 Markdown（`D:\Obsidian\SCM-Career` 下的 00-07/99 等文件夹）。
2. 生成器 = `build_site.py`（读取知识库 → 生成 `docs/` 静态站：index.html + files/ + assets/）。
3. 发布 = 本地每 10 分钟的定时任务 `SCM-Career-AutoSync`（`run_sync_hidden.vbs` → `update_site.ps1`）：
   `git pull --rebase` → 运行 `build_site.py` 重建 → `git add -A && commit` → `git push origin main` → GitHub Pages 自动构建 → 网页/手机可见。
4. 远端仓库：`https://github.com/WenXue-10/SCM-Career-Dashboard.git`（Pages 站点 wenxue-10.github.io/SCM-Career-Dashboard/）。

## 二、修法总原则
- **只改"源"（知识库 Markdown / build_site.py / site_assets/），不要直接改 `docs/` 生成物**（会被重建覆盖）。
- 改完文件即可，**不要手动 `git commit` 后不 push**：自动同步会在状态有改动时 add/commit/push。
  如需立即发布：手动 `git add -A && git commit && git push origin main`（git 在本机 Git Bash 可用）。
- 想立即看生成效果：在知识库根目录运行 `python build_site.py`（或让助手用环境内 python 运行），确认无报错、打开 `docs/index.html` 检查。

## 三、常见问题定位
| 现象 | 改哪里 |
|---|---|
| 某分类/文件夹没分组、全堆一起 | `build_site.py` 的 `_KB_META` / `_kb_01/_kb_02/_kb_03` 分组逻辑（03_笔面试题库已用 kb03） |
| 岗位汇总表/评分不对 | 检查 `01_岗位搜集与背调/公司调研/{公司}/{岗位}/评分-*.md` 的 frontmatter（Dataview 读取） |
| 样式/颜色/布局 | `site_assets/style.css`、`site_assets/body.html`、`site_assets/app.js`（构建时内联进 index.html） |
| 日报/时间线/待办 | `01_岗位搜集与背调/📅 岗位日报归档.md` 等源文件 |
| 简历展示 | `02_定制简历库/` 结构 + `build_site.py` 的 `_kb_02`/`scan_resumes` |
| build_site.py 报错 | 按 traceback 修，改后重跑 `build_site.py` 验证 |

## 四、build_site.py 关键函数速查
- `_KB_META`：知识库 9 个板块的元信息（icon/描述/处理器）。
- `_kb_01(jobs)` / `_kb_02(resumes)` / `_kb_03()`：01 岗位、02 简历、03 笔面试题库的分组逻辑。
- `scan_jobs()` / `scan_resumes()` / `scan_kb()`：读取并组装数据。
- 生成入口 `build()`：清空 docs → 复制素材 → 组装 → 写 index.html。
- 依赖：python 标准库 + `markdown`、`reportlab`（PDF 生成）。运行：`python build_site.py`。

## 五、注意
- 生成脚本用 UTF-8；新增中文文件夹/文件名注意保持一致。
- `docs/` 是生成目录，可整个重建；`site_assets/` 是手写的源（样式/模板/图标），**不要删**。
- 网页更新最迟 = 改完 + 10 分钟（自动同步）+ 1-2 分钟（Pages 构建）。

## ⚠️ 安全约束（修复网页时必读）
- 禁止执行 `git reset --hard`、`git clean`、`git rm`、删除/移动无关文件。
- 只改目标源文件（Markdown / build_site.py / site_assets/），改完等自动同步发布，或手动 git add+commit+push。
- 发现意外改动先停下问用户。
